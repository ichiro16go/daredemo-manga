## 1. プロダクトの目的とゴール

### 目的(Purpose)
- holonica-studioと同じコア価値 **「画力がないクリエイターが、アイデアさえあれば漫画制作の全工程をストレスなく完結できる」** を、独立サービスとして市場に投入し収益化する。
- holonicaがPCブラウザに限定しているのに対し、スマホ版アプリ(機能制限版)を提供することでスマホユーザー層を追加獲得し、ユーザー母数と収益機会を拡大する。これが holonica に対する唯一の差別化点。

### 計測可能なゴール(Goal) — holonicaの基準を流用(暫定値、後日調整可)
- KGI: リリース後3ヶ月で、有料会員数1,000人を達成する。
- KPI: 週間アクティブユーザー率(WAU)30%以上を維持する。
- 【要調整】上記はholonica-studio(PC専業)向けの目標をそのまま流用した暫定値。スマホ版ユーザーを含む前提で、DL数・フィード閲覧DAUなどのスマホ固有KPIは今後追加要否を検討する。

### 品質特性上のトレードオフ
- 開発期間(1ヶ月以内)を最優先する。PC版・スマホ版ともにスクラッチ新規実装のため、**スコープをMVPの4機能(後述)に絞ることが期日達成の前提条件**。追加機能の要望が出ても、まずこの期日とのトレードオフを都度確認する。

## 2. ターゲットユーザー

holonica-studioと同じペルソナ(ライトクリエイター層: 漫画で表現したいアイデアはあるが画力・専門スキルがなく形にできていない層)。
スマホ版により、SNSで漫画を「読む」ことが主目的の閲覧層も新たに取り込む。

## 3. サービス構成 — PC版とスマホ版の役割分担

daredemo-mangaは以下2つのクライアントを持つ、単一サービス(共通アカウント・DB)である。

| | PC版 | スマホ版(PWA) |
|---|---|---|
| 位置づけ | フル機能の漫画エディタ(holonica-studio相当) | 機能制限版・読者/入口アプリ |
| 主な機能 | 企画〜作画〜仕上げ〜投稿の全工程 | 読む機能 + キャラクター生成機能 |
| 実装方針 | 仕様を参考にスクラッチ新規実装(holonica-studioのコードは流用しない) | モバイルWeb/PWA。PC版と同一アカウント・DBを使用 |

## 4. 機能要件(MVPスコープ)

PC版はholonica-studio MVP要件定義書のF-01〜F-08を参考にスクラッチで実装する(詳細は別途、PC版向けに要件を整理する)。

スマホ版(PWA)のMVPスコープは以下2機能に限定する:

### 【SP-01: 読む機能】
ユーザーストーリー: ユーザーとして、PC版で他のユーザーが投稿した漫画作品を、スマホでSNSのフィードのように閲覧したい。
- 対象コンテンツ: PC版で投稿(公開)された作品のみ。スマホ版発の新規投稿フローはMVPに含めない。
- PC版と同一DBを参照するため、リアルタイム性の要件は低い(投稿後の反映タイミングは要検討)。

### 【SP-02: キャラクター生成機能】
ユーザーストーリー: ユーザーとして、スマホ上で自由な日本語テキスト、または参考画像+テキストでキャラクターを生成し、追加の指示で対話的に修正したい。
- PC版のキャラクター生成機能(F-02相当)と同水準。対話的な修正フローを含む。
- 生成したキャラクターはライブラリに保存され、PC版からも参照できる(同一アカウント・DBのため)。

## 5. スコープ外(MVPではやらないこと)

- スマホ版での漫画作品の制作・投稿(コマ組み・背景生成・自動着彩などの作画工程はPC版のみ)。
- 【将来拡張】構想メモ・共有機能: アイデアのメモを取り、他ユーザーと共有する機能。MVP後の拡張機能として別途要件定義する。
- ビジネス向け機能(チーム機能、法人プラン等)。
- 多言語対応(日本語のみ)。

## 6. 収益化モデル

フリーミアム + 広告のハイブリッド。
- 無料枠: 一定回数までキャラクター生成が可能。
- 有料: 生成回数追加・広告非表示などの課金(詳細は別途プライシング検討)。
- 広告: 無料ユーザーには広告を表示。
- 【要検討】具体的な価格・広告枠の仕様は未確定。次フェーズで詳細化する。

## 7. 非機能要件(暫定・要相談)

- データ基盤: holonica-studioとは完全に独立した新規Supabaseプロジェクト(またはPC版と共通の新規基盤)を用意する。holonicaの本番データには一切接続しない。
- 対応環境: PC版は主要Webブラウザ(Chrome, Safari, Edge)。スマホ版はモバイルブラウザ上のPWAとして主要スマホ(iOS Safari, Android Chrome)に対応。
- 性能: 画像生成処理は平均10秒以内(holonica基準を流用)。
- セキュリティ: ユーザーの登録情報・作品データは安全に保管し、本人以外から閲覧されないこと。

## 8. リスク・オープンイシュー

- **スケジュール**: PC版(フルエディタ)+スマホ版(PWA)を1ヶ月以内にスクラッチで新規実装するのは非常にタイト。holonica-studioの実績(F-01〜F-08フル実装)を踏まえると、まずPC版のMVP機能をさらに絞る(例: F-02, F-04, F-07のみ等)判断が必要になる可能性が高い。
- KGI/KPIはholonicaの基準を暫定流用しているが、スマホ発ユーザーの性質(閲覧中心)を考えると、有料会員数だけでなくDAU/フィード閲覧といった指標の追加が必要になる可能性がある。
- 「読む機能」がPC版DBを直接参照する設計のため、PC版の投稿(公開)フローの仕様確定が、スマホ版の実装着手条件になる。
